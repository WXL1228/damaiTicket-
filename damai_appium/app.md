# 安卓端 V2：预填购票流程

V2 的预填模式在开售前连接手机、核验演出详情和预填状态，缓存购买入口坐标；到点点击购买，优先保留有效预填，必要时按配置恢复票档和数量。流程经过选票页“确定”、原生订单确认核验、最终提交，再进入待支付／立即付款页；付款由用户完成。

当前已完成页面解析模拟与实机详情只读验证，原生订单确认、提交和锁单结果尚未经过真实下单验收。详情检查通过不保证后续页面能识别，不保证购票成功或手机执行、服务端锁单的时延。

## 运行准备

先按根目录 [README.md](../README.md) 安装 Python、Appium 3、UiAutomator2、Android SDK 和驱动所需 JDK。Windows PowerShell 启动 Appium 后保留此窗口：

```powershell
appium.cmd --port 4723
```

在大麦 APP 中登录，人工进入正确演出，完成场次、票档、数量和观演人预填，确认预填显示“已完成”，再返回演出详情。保持手机解锁、该详情在前台；准备完成后不要切页面、滚动或改变屏幕方向。

## 配置

编辑本目录 `config.jsonc`。它按标准 JSON 读取，不支持注释。下方是通用格式示例，不代表实际购票目标；演出、城市、场次、票档和名单需替换为真实信息，时间需替换为未来的实际开售时间：

```json
{
  "server_url": "http://127.0.0.1:4723",
  "keyword": "示例演出",
  "users": ["观演人姓名"],
  "city": "示例城市",
  "date": "2026-12-31 19:30",
  "price": "看台100元",
  "price_index": 0,
  "prefilled_mode": true,
  "if_commit_order": true,
  "sale_start_time": "2026-12-01 10:00:00",
  "order_flow_timeout": 60,
  "wait_poll_interval": 0.5
}
```

- `prefilled_mode: true`：使用独立预填流程，优先保留已生效的票档和正确数量；预填未生效时可恢复配置票档、按数量差额逐张加减，不重新勾选姓名。
- `if_commit_order: true`：在原生订单确认页核验通过后自动提交锁单，不包含任何自动付款。设为 false 则核对后停在确认页，尚未锁单。
- `sale_start_time`：预填模式必填，格式为 `YYYY-MM-DD HH:MM:SS`，按北京时间 UTC+8 解释，表示开售时间，不是演出时间。自动运行时必须仍在未来，过期会直接拒绝点击。
- `date` / `price`：真实演出场次与配置票档，用于订单确认页核对；`price` 也用于预填未生效时恢复票档。日期需包含完整年月日和需要核验的场次时间。
- `price_index`：从 0 开始的票档索引，价格文字不可读时作为恢复依据，必须按实际页面核对；可读价格与配置不符或该票档缺货时不改买其他价格。
- `users`：真实预填名单，不能重复；预期张数为名单人数。
- `order_flow_timeout`：首次购买点击后的页面处理等待时限，默认 60 秒，允许 1–180 秒；页面读取耗时会影响实际退出时刻。
- `wait_poll_interval`：旧模式查询间隔；预填模式使用独立准备和等待节奏。
- `udid` / `device_name` / `platform_version`：可选，按真实设备填写，多设备连接时用 `udid` 指定目标。

示例的 `2026-12-01 10:00:00` 一旦过期就不能复用。不要修改时间来绕过已有提交记录，应先在 APP 核对订单结果。

## 先做只读页面检查

从项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m damai_appium.damai_app_v2 --check-page
```

此命令只连接并读取页面，不点击、不购票、不等待开售。预填模式核验详情标题、预填“已完成”状态和购买栏边界，通过时输出坐标范围；已适配的购买栏文字隐藏、`clickable=false` 时也可根据边界准备。

诊断摘要保存在项目目录 `logs/mobile-page-check.json`，不保存原始 XML、截图或观演人数据。检查通过只表示当前详情准备通过，不代表真实下单验收完成。

## 提前运行并到点点击

可在开售前 3–5 分钟从项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m damai_appium.damai_app_v2
```

脚本提前建立 Appium 会话，首次读取整页 XML 核验详情并缓存入口；之后待命只轻量检查前台、锁屏状态、屏幕方向和尺寸，T−2 秒也不读取整页 XML。随后按本机单调时钟（monotonic）等待，T0 发送缓存坐标点击，不等待购买文字变更，不重新建立会话。终端的本机点击发送偏差不包含手机执行、网络和服务端处理时间，不能据此宣称毫秒锁单。按 `Ctrl+C` 可退出。

后续流程为：

1. 优先按 SKU 结构识别选票页，再判断提交文案，避免把选票“确定”当成最终提交。未选档时按钮可能视觉禁用而原生 `enabled=true`，因此必须等到实际数量可读且正确，才点击“确定”。
2. 预填票档未生效时，先按 `config.price` 匹配，必要时按已配置并核对过的 `price_index` 恢复。配置票档缺货或索引对应可读价格不符时停止，不换更贵或其他价格。
3. 实际数量已经等于观演人人数时不重复加票；不符则按差额逐个加减，每次等待页面回显，再调整下一张。数量回显失败不继续确认，不重新勾选姓名。
4. 点击选票“确定”后进入原生订单确认页，只读核对演出、场次、票档、数量及观演人，核验通过后精确最终提交一次；展示总额时也核对总额。
5. 取得订单号及待支付证据后才报告锁单。到待支付／立即付款页停止自动点击，由用户核对订单并付款，脚本不实际支付。

未知页面会继续只读分类至 `order_flow_timeout`，新模式不采用旧模式的开售后 3 秒接管规则。真正的平台验证码须本人在官方界面完成，程序等待并可继续观察后续页面。提交尝试发出后只核对结果，不再点击购买或提交。

只有原生订单确认核验通过后才写入最终提交记录，记录包含页面阶段、提交按钮及核验结果；选票“确定”不会写成最终提交。提交后若又回到选票页，按结果不明停止，不继续点“确定”或重复提交。

`logs/prefilled/` 保存跨重启防重复提交记录；即使提交点击超时、结果不明或进程退出，也不会自动再次提交同一目标。旧记录也不要随意删除，应先核对手机待支付订单。同一设备的重复购票进程通过操作系统锁阻止，进程退出后锁由系统释放。

## 旧模式兼容

`prefilled_mode: false` 或省略该字段会走旧流程：依赖可识别的购买文字，再按票档索引、名单人数和姓名操作。它可能覆盖已有预填，不适用于本指南的保留预填流程。

旧模式配置开售时间时，开售后 3 秒起的下一次页面查询仍未识别入口会停止，未配置时间则继续等待。新预填模式的隐藏入口点击、订单核验和防重复记录不适用于旧模式。
